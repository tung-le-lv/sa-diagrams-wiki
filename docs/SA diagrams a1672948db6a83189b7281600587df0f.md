# The diagrams I'd prioritize for a Software Architect

If you're preparing for a **Software Architect / Solution Architect interview**, don't try to master 50+ diagrams equally.

I'd rank them:

### Tier 1 — Must know

1. **System Context Diagram**
2. **C4 Container Diagram**
3. **C4 Component Diagram**
4. **Sequence Diagram**
5. **Deployment Diagram**
6. **Cloud Architecture Diagram**
7. **Data Flow Diagram**
8. **ERD**
9. **Domain Model**
10. **State Machine Diagram**
11. **Security/Auth Flow**
12. **Network Diagram**

### Tier 2 — Very important

1. **Bounded Context Map**
2. **Event-Driven Architecture Diagram**
3. **CQRS Diagram**
4. **Saga Diagram**
5. **Integration/API Diagram**
6. **CI/CD Diagram**
7. **DR/Failover Diagram**
8. **Observability Architecture**

10. Serverless architecture

## A very useful way to remember them

Instead of memorizing diagram names, think about the **question you're trying to answer**:

| Question | Diagram |
| --- | --- |
| **What is our system?** | Context |
| **What are its major pieces?** | C4 Container |
| **What's inside a service?** | Component |
| **How do requests flow?** | Sequence |
| **How does data move?** | Data Flow |
| **How is data structured?** | ERD |
| **How is the domain structured?** | Domain Model |
| **How do services communicate?** | Integration / Event Flow |
| **Where does it run?** | Deployment |
| **How is the network structured?** | Network |
| **How does authentication work?** | Security/Auth Flow |
| **What happens when something fails?** | Resilience / Failover |
| **How is it deployed?** | CI/CD |
| **How do we monitor it?** | Observability |
| **How are business processes executed?** | BPMN / Workflow |
| **Why did we choose this architecture?** | ADR / Decision Matrix |

**The most important skill isn't knowing how to draw all these diagrams. It's knowing which diagram communicates a particular architectural decision most effectively.**

For someone with a **.NET + microservices + DDD + event-driven + AWS/Azure** background, I'd especially focus on **C4, sequence, deployment/cloud, DDD bounded-context, event-driven, data-flow, security, and resilience diagrams**.
