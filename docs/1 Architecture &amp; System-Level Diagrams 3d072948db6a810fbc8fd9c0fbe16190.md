| Diagram | What it answers |
| --- | --- |
| **System Context Diagram** | Who/what interacts with our system? |
| **Container Diagram** | What are the major applications/services/data stores? |
| **Component Diagram** | What components exist inside a service/application? |
| **Deployment Diagram** | Where does everything run? |
| **Solution Architecture Diagram** | How does the whole solution fit together? |
| **Logical Architecture Diagram** | What are the major logical building blocks? |
| **Physical Architecture Diagram** | What infrastructure actually hosts them? |
| **Cloud Architecture Diagram** | How do AWS/Azure/GCP resources fit together? |
| **Reference Architecture** | What architecture pattern should teams follow? |
| **Landscape Diagram** | What systems exist across the organization? |

### Especially important: C4 Model

As an architect, I would prioritize:

**Context → Container → Component → Code**

You generally don't need to draw the Code level unless developers need it.
